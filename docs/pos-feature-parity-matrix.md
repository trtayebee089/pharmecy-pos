# Red Pharma POS – Feature Parity Matrix (legacy Blade → Nuxt 3 + centralized Laravel API)

- **Legacy system (read-only):** `D:\01 REDPHARMA\00 CODEBASE\backend - ocr pos\` (Laravel 10.48.29, SalePro-derived Blade app).
- **Target:** Nuxt 3 POS front end over a centralized Laravel API; staff channel `/api/pos/v1/*` (Sanctum SPA cookie), customer channel `/api/*` and `/api/v1/*` kept compatible.
- **Inputs:** `docs/workpapers/wp1-navigation-core.md`, `wp2-navigation-admin.md`, `wp4-api-consumers.md`, `wp5-workflows-security.md`. Line references are inherited from those workpapers (static reading; nothing was executed). Items marked UNVERIFIED there remain UNVERIFIED here.
- **Status:** nothing has been built or tested yet. Every row is **Not started** / **Not verified**.
- **Rows:** 450 feature rows (one per user-visible feature or action, including hidden routes and modules), plus the customer-facing API inventory at the end.

## Legend

| Term | Meaning |
|---|---|
| Existing route | The page (or entry point) the user opens in the legacy app. `W:n` = `routes/web.php` line; `MAIN` = `layout/main.blade.php`; `SB` = sidebar. |
| Existing API endpoint | The legacy web/AJAX/form route (method + path) the feature calls. These are session + CSRF web routes, **not** a JSON API. Any `/api` route is named explicitly. "**404**"/"**500**" = currently broken. |
| "None — needs /api/pos/v1" | No JSON API exists; the Nuxt POS needs a new endpoint under `/api/pos/v1`. This applies to **every** staff-side feature in sections 1–34 even where not repeated in Notes. |
| Required permissions | Legacy Spatie permission names. "(page)"/"(sidebar)" = only the page or menu is gated; "none" = no server-side check on the action (wp5 B-AUTH-1). New API must enforce permissions on every endpoint. |
| **Rec: Migrate** | Port behaviour largely as-is (with permission checks and validation added). |
| **Rec: Redesign** | Keep the business capability, rebuild the logic/data model (e.g. server-side totals, ledger, state machine). |
| **Rec: Preserve** | Working, valuable behaviour; port carefully with minimal change. |
| **Rec: Retire-candidate — needs business confirmation** | Hidden, dead, broken, vendor or non-pharmacy feature; do not build unless the business confirms it is needed. Security-critical vendor endpoints should additionally be removed from the legacy app now. |
| **Rec: Fix-before-migrate** | A defect corrupts stock, money or security; the correct behaviour must be specified (and the legacy data repaired) before porting. |
| CRITICAL | Linked bug of Critical severity in wp1/wp2/wp5 (e.g. B-SEC-1, B-BIZ-1). Bug IDs `B-*` refer to wp5 Part B; `R*`/`X*` to wp1. |
| Pharmacy concerns | Batch/expiry, FEFO allocation, expired-stock blocking, box/strip/piece units, client-trusted prices/totals, generic-name search. |
| New implementation status | Always "Not started" at this point. |
| Verification status | Always "Not verified" at this point. |
